Career OS Template
이력서가 매번 새로 시작된다면

지원 과정을 OS처럼 만들자

자료 저장부터 JD 맞춤 패키지까지 한 흐름으로.

01 / 08
문제

지원할 때마다 자료가 흩어진다

“이 프로젝트 설명 어디 있었지?” 수치, 링크, 수상, 회고, JD 분석이 따로 놀면 매번 새 문서를 다시 쓰게 된다.

Career OS는 원천 자료와 제출 문서를 분리해, 같은 사실을 여러 산출물에 안정적으로 재사용하게 만든다.

02 / 08
핵심 구조

3개 레이어로 나눈다

raw/ 사실 원형, 링크, 메모를 보존
wiki/ 경험, 프로젝트, 스토리, 문장 뱅크로 정규화
outputs/ 범용본과 회사별 제출 패키지 생성

핵심은 제출 문서를 바로 고치는 게 아니라, 먼저 wiki를 갱신하고 산출물을 다시 만드는 것이다.

03 / 08
사용 순서

처음 쓰는 사람은 이 순서대로

01 index 확인
02 career-ingest
03 general build
04 career-apply-pipeline
05 rendered output
06 quality check
04 / 08
핵심 스킬

JD 하나를 넣으면 패키지까지 이어진다

JD 저장
회사 조사
전략 수립
resume
portfolio
polish
HTML/PDF
품질 체크

`career-apply-pipeline`은 하위 스킬들을 순서대로 묶는 상위 런북이다.

05 / 08
템플릿 구성

가져가면 바로 있는 것들

examples/프로젝트, 경력, 수상, JD 입력 예시
wiki/샘플 후보의 정규화 지식과 템플릿
skills/ingest, general build, custom package, render, lint 워크플로
resume/개인정보 없는 HTML 이력서 스타터
portfolio/개인정보 없는 HTML 포트폴리오 스타터
06 / 08
브랜치 전략

개인 자료와 템플릿은 분리한다

main 실제 커리어 위키
career-os-template 개인정보 제거 후 샘플화
떼어낼 기준점 템플릿 브랜치를 별도 레포로 만들면, 다른 사람은 자기 raw와 wiki만 채워서 시작할 수 있다.
07 / 08
다음 액션

복사한 뒤 자기 자료를 넣으면 된다

  • 샘플 후보명과 링크를 자기 정보로 교체
  • 프로젝트와 경력을 raw/에 저장
  • career-ingest로 wiki를 채우기
첫 사용 명령 “이 자료를 career-ingest 기준으로 반영해줘”
템플릿 브랜치 열기
