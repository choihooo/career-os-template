# JD Analysis

## Target Role

React와 TypeScript 기반 B2B SaaS 프론트엔드 엔지니어. 운영자가 반복 사용하는 대시보드, 테이블, 필터, 폼 화면을 제품 요구사항과 API 상태에 맞춰 구현하는 역할이다.

## Must-have Requirements

- React/TypeScript 기반 제품 화면 구현
- API 응답, 서버 상태, URL 상태를 고려한 상태 설계
- 폼, 테이블, 대시보드 등 업무용 UI 구현
- 사용자 흐름을 기준으로 요구사항을 화면 구조로 구체화
- Git 기반 협업과 코드 리뷰

## Preferred Requirements

- TanStack Query, Zod, Recharts 사용 경험
- 어드민 또는 B2B SaaS 제품 개발 경험
- QA 이슈를 재현하고 입력 단계에서 차단한 경험
- 사용자 피드백을 바탕으로 반복 업무 시간을 줄인 경험

## Repeated Keywords

- React
- TypeScript
- 대시보드
- 상태관리
- API 연동
- 폼 검증
- 운영자 흐름
- 유지보수성

## Persona Match

- Strong match: `OpsPulse Dashboard`에서 TanStack Query로 서버 상태를 분리하고, URL query로 필터 상태를 공유 가능하게 만든 경험.
- Strong match: `모멘텀랩스`에서 Zod 스키마와 명시 타입을 적용해 QA 재현 이슈 5건 중 4건을 입력 단계에서 차단한 경험.
- Strong match: `ReviewFlow Admin`에서 상태별 탭, 상세 패널, 액션 버튼 상태를 나눠 운영자 검토 흐름을 정리한 경험.
- Supporting match: Recharts를 사용해 운영 지표와 추세를 한 화면에서 확인하도록 만든 경험.

## Evidence Level

- 직접 사용 가능: React, TypeScript, TanStack Query, Zod, Recharts, URL query state, 어드민 UI, 폼 검증.
- 조건부 사용: 리포트 작성 시간 2시간에서 30분 감소는 운영자 피드백 기반이므로 실제 제출 전 측정 방식과 원문을 보강한다.
- 약하게 표현: Git 기반 코드 리뷰는 구체 PR 링크가 없으므로 "협업 문서화와 QA 재현 경로 정리" 중심으로 표현한다.

## Gaps

- 이 패키지는 가상 페르소나 기반 예시다.
- 실제 제출 전 회사명, GitHub 링크, PR 링크, 스크린샷, 사용자 피드백 원문으로 교체해야 한다.
- 대규모 트래픽, 매출, 인프라 성과처럼 raw 근거가 없는 표현은 사용하지 않는다.
