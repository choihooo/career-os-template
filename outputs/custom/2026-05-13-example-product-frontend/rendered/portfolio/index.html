OpsPulse Dashboard

2025.07-2025.08

React TypeScript TanStack Query Recharts

프로젝트 소개

광고비, 주문 수, CS 문의 수를 CSV로 따로 내려받아 만들던 주간 리포트를 한 화면으로 모은 대시보드입니다.

담당 역할

프론트엔드 리드로 서버 상태, 필터 상태, 차트 시각화 흐름을 설계하고 구현했습니다.

  • TanStack Query 기반 서버 상태 분리
  • URL query 기반 필터 조건 동기화
  • Recharts 기반 주요 지표와 추세 시각화

1. 문제 상황

  • 운영자가 광고비, 주문 수, CS 문의 수를 CSV로 따로 내려받아 주간 지표를 확인
  • 필터 조건 공유와 같은 조건 재현이 어려움

2. 결과

  • 주간 리포트 작성 시간이 2시간에서 30분으로 줄었다는 운영자 피드백 확보
  • 필터 조건 공유와 재현이 쉬워졌다는 정성 피드백 확보

- 2 -

TanStack Query + URL query 상태 설계

1. 문제 상황

  • 필터 변경과 데이터 요청이 한 컴포넌트 안에 섞여 변경 영향 범위가 커짐
  • 운영자가 동일 조건을 공유해도 화면 상태가 재현되지 않음

2. 행동

  • 서버 데이터 요청과 캐시 관리는 TanStack Query로 이동
  • 필터 조건은 URL query로 직렬화하고 화면 진입 시 복원
  • 차트와 테이블은 같은 query state를 기준으로 렌더링

3. JD 연결점

  • 대시보드 UI, API 연동 구조, 서버 상태 관리, 운영자 흐름 개선 요구와 직접 연결
  • 업무용 화면에서 상태 설계 판단을 설명할 수 있는 사례로 사용

- 3 -

ReviewFlow Admin

React · URL query · Table UI · Review workflow

1. 문제 상황

  • 검토 담당자가 신청 상태, 누락 서류, 담당자 메모를 여러 화면에서 확인
  • 필터 조건 공유가 어려워 스크린샷이나 구두 설명에 의존

2. 행동

  • 상태별 탭과 리스트 필터를 URL query로 동기화
  • 상세 패널에서 누락 서류, 담당자 메모, 처리 액션을 한 번에 확인하도록 배치
  • 액션 버튼의 loading, disabled, error 상태를 명시해 중복 처리 가능성을 낮춤

3. 결과

  • 같은 조건의 검토 큐를 팀원에게 링크로 전달할 수 있게 됨
  • 화면 이동 없이 누락 서류와 처리 상태를 확인할 수 있다는 정성 피드백 확보

- 4 -

FormGuard System

TypeScript · Zod · Form component · Accessibility

1. 문제 상황

  • 폼마다 입력 상태와 에러 메시지 표현이 달라 QA 피드백이 반복
  • 사용자가 어떤 입력을 잘못했는지 화면에서 바로 알기 어려움

2. 행동

  • Zod 스키마로 입력 데이터의 구조와 검증 기준을 명시
  • label, helper text, error text, disabled state의 우선순위를 정의
  • 키보드 접근과 focus ring 동작을 점검해 기본 사용성을 보강

3. 결과

  • QA 재현 이슈 5건 중 4건을 사전 검증 단계에서 차단
  • 신규 폼 화면에서 상태별 UI 리뷰 기준이 명확해짐

Dashboard UI
