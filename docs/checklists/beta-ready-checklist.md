# Beta Ready Checklist

내부 베타 100% 기준이다. 다른 사용자가 설명을 거의 듣지 않고도 따라 할 수 있어야 한다.

## Onboarding

- [ ] README 첫 화면에서 이 제품이 무엇을 하는지 알 수 있다.
- [ ] 처음 10분 안에 어떤 파일을 읽고 무엇을 입력해야 하는지 알 수 있다.
- [ ] `examples/`에 프로젝트, 경험, 수상, JD, 요청 프롬프트 예시가 있다.

## Output Clarity

- [ ] `raw/`, `wiki/`, `outputs/`, `resume/`, `portfolio/`의 역할 차이가 명확하다.
- [ ] markdown 산출물과 HTML/PDF 렌더링 산출물의 관계가 설명되어 있다.
- [ ] 회사별 맞춤 패키지의 폴더 구조가 예시와 함께 설명되어 있다.

## Failure Handling

- [ ] JD가 너무 짧거나 링크 접근이 안 될 때의 처리 방식이 설명되어 있다.
- [ ] 근거 없는 수치를 만들지 않는다는 규칙이 명시되어 있다.
- [ ] 부족한 정보는 `Gaps` 또는 `analysis.md`에 남긴다는 규칙이 있다.

## Reproducibility

- [ ] `outputs/custom/2026-01-01-example-frontend/` 샘플 패키지가 있다.
- [ ] 샘플 JD에서 analysis, strategy, resume, portfolio가 어떻게 생성되는지 확인할 수 있다.
- [ ] `index.md`가 새 페이지와 샘플을 찾을 수 있게 연결한다.
