# Positioning

이 페이지는 산출물의 톤과 선택 기준을 정한다. 샘플 문장은 자기 경험에 맞게 교체한다.

## Main Narrative

- 핵심 내러티브: 사용자 흐름과 유지보수성을 함께 개선하는 React/TypeScript 프론트엔드 엔지니어
- 설득 근거: 타입 안정성 개선, URL 상태 동기화, API 데이터 흐름 정리, 대시보드 시각화
- 약해지는 경우: 대규모 트래픽, 매출 직접 기여, 백엔드 인프라 주도 경험을 요구하는 JD

## Target Roles

- Role 1: Frontend Engineer
  - 필요한 증거: React/TypeScript, 상태관리, API 연동, 사용자 흐름 개선
  - 강조할 프로젝트: Sample Company, Sample Dashboard
- Role 2: Product Engineer
  - 필요한 증거: 문제 정의, 사용자 피드백, 실험과 검증
  - 강조할 프로젝트: Sample Dashboard
- Role 3: Frontend Platform Engineer
  - 필요한 증거: 공통 컴포넌트, 테스트, 문서화, 반복 비용 감소
  - 강조할 프로젝트: 관련 경험이 있으면 추가

## Repeated Strengths

- Strength: 운영 안정성 개선
  - Definition: 오류가 사용자나 운영 단계에 도달하기 전에 타입과 검증으로 차단한다.
  - Evidence pages: `samples/wiki/experiences/sample-company.md`
- Strength: 상태관리와 데이터 흐름 설계
  - Definition: UI 상태와 서버 상태를 분리하고 재현 가능한 흐름을 만든다.
  - Evidence pages: `samples/wiki/projects/sample-dashboard.md`
- Strength: 사용자 흐름 중심 UX 개선
  - Definition: 입력, 필터, 탐색, 알림처럼 사용자가 막히는 지점을 줄인다.
  - Evidence pages: `samples/wiki/projects/sample-dashboard.md`

## Claims to Avoid

- 아직 근거가 부족한 주장: 대규모 트래픽 최적화, 매출 성장 기여, 조직 전체 리딩
- 너무 넓은 주장: 풀스택 전반 역량, AI 서비스 전반 설계, 비즈니스 전략 수립
