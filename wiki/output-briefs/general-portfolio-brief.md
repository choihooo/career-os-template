# General Portfolio Brief

범용 포트폴리오 v1/v2를 만들 때의 조립 기준이다. 이 파일은 최종 제출물이 아니라 출력 지시서다.

## Portfolio v1

### Intent

- 프로젝트와 증거를 균형 있게 보여주는 기본 포트폴리오
- 빠르게 훑어도 역할, 문제, 기여, 결과가 보이게 구성

### Reader Should Learn

- 어떤 프로젝트를 해왔는가
- 각 프로젝트에서 맡은 역할은 무엇인가
- 결과와 증거는 무엇인가
- 이력서에 적힌 강점이 실제 작업으로 어떻게 드러나는가

### Case Study Shape

- Project:
- Context:
- Problem:
- My Role:
- What I Did:
- Result:
- Proof:
- Tools or Skills:

### Selection Rules

- 프로젝트 수보다 각 프로젝트의 완성도를 우선한다.
- 이미지, 링크, 결과물이 있는 프로젝트를 먼저 배치한다.
- `wiki/stories/story-bank.md`에 있는 이야기는 케이스 스터디의 중심 서사로 쓴다.

## Portfolio v2

### Intent

- 포지셔닝 중심의 내러티브형 포트폴리오
- 목표 역할이 명확하거나 회사별 맞춤 전 단계에서 사용
- `portfolio/` 템플릿으로 옮길 때는 A4 세로 페이지 기준으로 압축한다.

### Reader Should Learn

- 이 후보자가 어떤 관점으로 문제를 보는가
- 프로젝트 사이에 반복되는 강점은 무엇인가
- 실무에서 어떤 판단을 해왔는가

### Section Order

1. Narrative
2. Signature Strengths
3. Selected Case Studies
4. Evidence and Links
5. Appendix if needed

### Selection Rules

- `wiki/themes/positioning.md`의 Differentiators와 직접 연결되는 프로젝트를 우선한다.
- 프로젝트 설명은 기능 목록이 아니라 문제와 판단 중심으로 쓴다.
- 수치가 없으면 정성적 결과와 증거 링크를 분리해 적는다.

## Quality Bar

- 각 케이스 스터디는 "문제-판단-행동-결과"가 보여야 한다.
- 디자인 이미지나 링크가 필요한 프로젝트는 Missing Evidence에 남긴다.
- 이력서와 같은 문장을 그대로 반복하지 않는다.
- 제출용 문서에는 "준비 중"이나 placeholder를 남기지 않는다.

## HTML Deck Mapping

- Cover: 포지셔닝, 연락처, 가장 강한 증거
- Overview: 프로젝트 선택 기준과 대표 프로젝트 목록
- Case Study: 문제, 역할, 결과, 큰 시각 자료
- Process: 맥락, 판단, 실행, 결과
- Proof: 링크, 재사용 강점, 지원 역할과의 연결
