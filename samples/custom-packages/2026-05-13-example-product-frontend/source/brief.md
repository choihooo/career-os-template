# Application Brief

## Target Role

React와 TypeScript 기반 B2B SaaS 프론트엔드 엔지니어. 운영자가 반복 사용하는 대시보드, 테이블, 필터, 폼 화면을 제품 요구사항과 API 상태에 맞춰 구현하는 역할이다.

## Must-have Requirements

- React/TypeScript 기반 제품 화면 구현
- API 응답, 서버 상태, URL 상태를 고려한 상태 설계
- 폼, 테이블, 대시보드 등 업무용 UI 구현
- 사용자 흐름을 기준으로 요구사항을 화면 구조로 구체화
- Git 기반 협업과 코드 리뷰

## Preferred Requirements

- TanStack Query, Zod, Recharts 사용 경험
- 어드민 또는 B2B SaaS 제품 개발 경험
- QA 이슈를 재현하고 입력 단계에서 차단한 경험
- 사용자 피드백을 바탕으로 반복 업무 시간을 줄인 경험

## Evaluation Themes

- 운영자 흐름을 화면 구조와 상태 설계로 풀어내는 역량
- API 응답과 화면 상태를 분리하는 제품형 프론트엔드 역량
- 입력 검증과 QA 재현 비용을 줄이는 품질 감각

## What To Emphasize

- TanStack Query 기반 서버 상태 분리
- URL query 기반 필터 공유와 재현성
- Zod 기반 입력 검증과 타입 안정성
- 운영자가 반복하던 리포트 확인 흐름을 줄인 대시보드 경험
- 검토 큐, 상세 패널, 액션 버튼 상태를 나눈 어드민 워크플로 경험

## What To De-emphasize

- 대규모 트래픽, 매출, 인프라 성과처럼 raw 근거가 없는 표현
- 백엔드/데이터 파이프라인을 주도한 것처럼 보이는 표현
- 실제 증빙이 없는 정량 성과의 단정적 표현

## Leading Projects And Stories

- `OpsPulse Dashboard`: 운영자 리포트 흐름 개선과 필터 재현성
- `ReviewFlow Admin`: 검토 큐, 상세 패널, 액션 상태 설계
- `FormGuard System`: 폼 검증과 컴포넌트 상태 규칙

## Gaps And Claims To Avoid

- 이 패키지는 가상 페르소나 기반 예시다.
- 실제 제출 전 회사명, GitHub 링크, PR 링크, 스크린샷, 사용자 피드백 원문으로 교체해야 한다.
- 리포트 작성 시간 2시간에서 30분 감소는 운영자 피드백 기반이므로 실제 제출 전 측정 방식과 원문을 보강한다.
